# =============================================================================
# MULEGUARD backend development requirements
# -----------------------------------------------------------------------------
# Purpose:
#   Development, testing, linting, typing, security, schema, reporting,
#   supply-chain, and debugging dependencies for the MULEGUARD backend.
#
# IMPORTANT:
#   Do NOT install this file into production runtime images.
#   Production/runtime images should use:
#
#     pip install -r backend/requirements.txt
#
#   Development environments should use:
#
#     pip install -r backend/requirements-dev.txt
#
#   Or, if using the packaged project definition:
#
#     pip install -e "backend[dev]"
#
# Design rules:
#   - Python 3.11+
#   - Synthetic-first prototype
#   - Modular monolith backend
#   - Typed FastAPI / Pydantic / SQLAlchemy / Alembic stack
#   - Deterministic tests wherever possible
#   - Security and supply-chain hygiene included
#   - No real banking integrations
#   - No Kafka/Kubernetes/microservice platform dependencies by default
#   - No deep learning, GNN, LLM, vector-database, or experimental platform
#     dependencies by default
#   - Optional packages remain commented unless implemented, tested, and
#     documented
#
# Reproducibility guidance:
#   This file uses thoughtful version ranges for maintainability.
#   For CI-critical or production-like development locks, generate an exact
#   locked file after tests pass, for example:
#
#     pip install pip-tools
#     pip-compile backend/pyproject.toml --extra dev -o backend/requirements-dev.lock
#
#   Then install from the locked file:
#
#     pip install -r backend/requirements-dev.lock
#
#   For hashed locks, use:
#
#     pip-compile --generate-hashes backend/pyproject.toml --extra dev \
#       -o backend/requirements-dev.lock
#
# =============================================================================

# 5. Static type checking
# -----------------------------------------------------------------------------
# Mypy is the primary static type checker for the backend.
mypy>=1.11,<2.0

# Type stubs: NOT installed by default, and deliberately so.
#
# `types-PyJWT` was pinned here as `>=2.8,<3.0` and no such release exists --
# the stub package stopped at 1.7.1 when PyJWT 2.x started shipping its own
# `py.typed`, so the stubs became redundant and were never versioned to match.
# pip could not satisfy it, and because pip resolves the whole requirement set
# before installing anything, that one impossible pin meant NOTHING was
# installed: not pytest, not alembic, not fastapi. A single bad stub pin took
# down the entire environment.
#
# The same thing is waiting to happen to the others. A stub package's version
# is not tied to the library it describes, and a stub gets yanked the moment
# upstream ships inline types. None of these are needed to run the
# application or the test suite -- only `mypy` consumes them -- so they do not
# belong in the file that has to install cleanly for anything to work.
#
# If you run mypy and it reports missing imports, install the stubs it names,
# on the day you need them, unpinned:
#
#   python -m pip install types-PyYAML types-python-dateutil types-requests
#   python -m mypy --install-types        # or let mypy fetch them itself
#
# PyJWT, jsonschema and psycopg2 all ship inline types now, so there is
# nothing to install for those.

# =============================================================================
# Explicitly excluded by design
# -----------------------------------------------------------------------------
# The following categories are intentionally absent from default development
# requirements:
#
#   - Real banking/payment integrations
#   - Kafka / RabbitMQ / NATS / Pulsar clients
#   - Kubernetes operators/clients for application logic
#   - Airflow / Prefect / Dagster / dbt / Spark / Dask / Ray
#   - PyTorch / TensorFlow / JAX / Transformers / LLM SDKs
#   - LangChain / LlamaIndex / OpenAI / Anthropic / Mistral / Ollama clients
#   - Graph neural network libraries such as PyTorch Geometric / DGL /
#     StellarGraph
#   - Vector databases and embedding stacks such as FAISS / Chroma / Qdrant /
#     Weaviate / Pinecone / Milvus / pgvector clients
#   - External cybercrime/intelligence feeds
#   - Deanonymisation, OSINT, covert surveillance, or automatic enforcement
#     tooling
#
# If any of these are ever considered, they require:
#   - an Architecture Decision Record;
#   - a security review;
#   - a model-risk review;
#   - updated docs/model-card.md and docs/security.md;
#   - tests proving no leakage, no unsafe automation, no unbounded graph access,
#     no fake functionality, and no real customer data exposure.
# =============================================================================

#   cd backend

#   detect-secrets scan > .secrets.baseline
