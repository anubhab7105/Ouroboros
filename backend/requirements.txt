# =============================================================================
# MULEGUARD backend runtime requirements
# -----------------------------------------------------------------------------
# Purpose:
#   Runtime Python dependencies for the MULEGUARD FastAPI backend.
#
# Install:
#   pip install -r backend/requirements.txt
#
# Development/test/lint/type/security tools:
#   pip install -r backend/requirements-dev.txt
#
# Design rules:
#   - Python 3.11+
#   - Synthetic-first prototype
#   - Modular monolith
#   - No real banking integrations
#   - No Kafka/Kubernetes/microservice fleet dependencies
#   - No deep learning, GNN, LLM, vector-database, or experimental platform
#     dependencies by default
#   - Every runtime package below supports a documented MULEGUARD capability
#   - Optional packages remain commented unless implemented, tested, and
#     documented
#
# Reproducibility guidance:
#   This file uses thoughtful version ranges for maintainability.
#   For production-like or regulated deployments, generate an exact lockfile
#   after CI passes, for example:
#
#     pip install pip-tools
#     pip-compile backend/pyproject.toml --extra dev -o backend/requirements.lock
#
#   Then build images from the locked file.
# =============================================================================

# 5-7. Numerical, machine-learning and graph stack  --  NOT REQUIRED
# -----------------------------------------------------------------------------
# These five packages are deliberately NOT installed, because nothing in
# `app/`, `tests/` or `scripts/` imports any of them. Verify before changing:
#
#   grep -rE "^\s*(import|from)\s+(numpy|pandas|scipy|sklearn|networkx)" \
#       --include="*.py" app/ tests/ ../scripts/
#
# That returns nothing. The implementation went a different way than an early
# draft of this file assumed:
#
#   - `app/ml/` is pure-Python. The supervised baseline, the anomaly scorer,
#     the feature builder, the splitter and the metrics are all implemented
#     directly, with no scikit-learn, no numpy and no compiled extension in
#     the request path. That was a deliberate choice: a detection platform
#     that cannot score because a wheel failed to build is worse than a
#     simpler model that always runs. It also means `app/ml/` imports the
#     standard library only, so training and scoring work offline.
#   - `app/graph/` and `app/services/graph.py` implement bounded traversal,
#     degree and weighted metrics, cycle candidates and money-trail search
#     against the database directly. The database is the source of truth and
#     the traversal has to respect per-query bounds and emit caveats, which is
#     not something a general graph library does for you.
#
# Installing them anyway costs roughly 400 MB and brings in the single most
# version-fragile corner of the Python ecosystem: numpy's 1.x/2.x boundary
# against whatever scipy and scikit-learn currently require. Pinning
# `numpy<2.0` next to an unpinned modern scikit-learn is how a `pip install`
# ends up backtracking for twenty minutes and then failing.
#
# If you add real scikit-learn models later, uncomment these and pin numpy and
# scikit-learn together as one compatible pair, not independently:
#
# numpy>=1.26,<3.0
# pandas>=2.2,<3.0
# scipy>=1.11,<2.0
# scikit-learn>=1.4,<2.0
# networkx>=3.2,<4.0

# =============================================================================
# Explicitly excluded by design
# -----------------------------------------------------------------------------
# The following categories are intentionally absent from runtime requirements:
#
#   - Real banking/payment integrations
#   - Kafka / RabbitMQ / NATS / Pulsar clients
#   - Kubernetes operators/clients for application logic
#   - Airflow / Prefect / Dagster / dbt / Spark / Dask / Ray
#   - PyTorch / TensorFlow / JAX / Transformers / LLM SDKs
#   - LangChain / LlamaIndex / OpenAI / Anthropic / Mistral / Ollama clients
#   - Graph neural network libraries such as PyTorch Geometric / DGL / StellarGraph
#   - Vector databases and embedding stacks such as FAISS / Chroma / Qdrant /
#     Weaviate / Pinecone / Milvus / pgvector clients
#   - External cybercrime/intelligence feeds
#   - Deanonymisation, OSINT, covert surveillance, or automatic enforcement
#     tooling
#
# If any of these are ever considered, they require:
#   - an ADR;
#   - a security review;
#   - a model-risk review;
#   - updated docs/model-card.md and docs/security.md;
#   - tests proving no leakage, no unsafe automation, and no fake functionality.
# =============================================================================
